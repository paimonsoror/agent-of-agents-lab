Get started

One VM, one command

The whole fleet builds inside a KIND cluster on a single Linux VM. First build on a fresh VM takes six to twelve minutes, dominated by image pulls. Re-running make up when nothing changed takes under a minute.

1. Prerequisites

ItemRequirement
HostLinux VM, x86_64 or arm64, 8+ cores, 12+ GiB RAM (sized for 15 GiB), 30 GB free disk
DockerEngine 24+ with the buildx plugin; the build user in the docker group

NetworkOutbound HTTPS to Docker Hub, quay.io, cr.agentgateway.dev, ghcr.io, PyPI and api.anthropic.com
Ports30080–30085 free on the host

2. The one secret

The Anthropic API key is the only secret. It is read at deploy time and written into a Kubernetes Secret in each namespace that runs a model loop. It is never stored in the repository or in Helm values.

git clone https://github.com/paimonsoror/agent-of-agents-lab.git
cd agent-of-agents-lab

mkdir -p ~/.maestro && chmod 700 ~/.maestro
echo 'ANTHROPIC_API_KEY=sk-ant-...' > ~/.maestro/secrets.env && chmod 600 ~/.maestro/secrets.env

3. Build, prove, open

make up        # cluster, monitoring, images, chart, wait, smoke test
make urls      # every URL
make smoke     # re-run the health proof any time
make down      # delete the cluster; make reset = down + up

From a workstation you can drive a remote VM instead: make remote-up VM=user@host SSH_KEY=~/.ssh/key rsyncs the repository to the VM and runs make up there. The host IP is auto-detected; override with make up HOST_IP=10.0.0.5 on a VM with several interfaces.

6. Same agents, from your IDE

TOKEN=$(make -s token-engineer)          # or: token-sre-lead
claude mcp add --transport http maestro       http://HOST_IP:30083/maestro/mcp --header "Authorization: Bearer $TOKEN"
claude mcp add --transport http domain-agents http://HOST_IP:30083/agents/mcp  --header "Authorization: Bearer $TOKEN"

Tokens last eight hours. engineer will not see the messaging_* tools; sre-lead sees everything. Copilot and Cursor setup is in docs/ide-setup.md.

8. Adding a domain

Write skills/<domain>-observability/SKILL.md (most of the work, and the most valuable part), add a tool module under agents/domain-agent/domains/, a platform plus exporter plus agent Deployment in the chart, a gateway target and authorisation rule, a realm role, a Grafana dashboard, a console node and a fault scenario. Record it in an ADR. Maestro does not change.
