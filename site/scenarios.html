Fault injection

A healthy system makes for a dull demo

Each domain ships one reversible fault that makes it the culprit. No synthetic metrics: the faults are real changes to the running platforms, so the agents read real signals. Inject one below to see the metric the agent watches and the verdict it returns.

Active state is never stored. The console and make scenario-status both derive it from the cluster (an annotation, a Job, a replica count), so they always agree. ADR-0011.

The member portal's load generator runs continuously so every metric has a baseline, and the edge gateway reloads its mounted config within about a minute of the ConfigMap change. Scenarios are applied from the console or with make scenario-<name>; make up clears all of them so every build starts from the baseline.

The APIM scenario doubles as the change-management story: the agent finds the change id and recommends the rollback, exactly as in the reference sketch where ServiceNow would hold the change record.
